# moumd-skills

**moumd CLI 사용법 스킬 문서 + 프로젝트 템플릿 카탈로그.**

| 디렉토리 | 내용 |
|---|---|
| [`skills/moumd-cli/SKILL.md`](skills/moumd-cli/SKILL.md) | 에이전트가 `moumd` 를 쓰는 법 |
| [`templates/catalog.yaml`](templates/catalog.yaml) | 프로젝트 템플릿 목록 (주소만; 콘텐츠는 각자의 저장소에) |
| [`AGENTS.md`](AGENTS.md) | 이 저장소를 편집하는 에이전트를 위한 지침 |

## 설계에서 가장 중요한 한 가지

**명령이 무엇인지에 대한 권위는 이 저장소가 아니라 `moumd catalog --format json` 이다.**

그래서 스킬 문서는 *"어떤 verb 가 있는지"* 를 나열하지 않고 *"어떻게 찾는지"* 를 가르친다.
verb 목록을 여기 복제하면 그것은 두 번째 출처가 되고, 다음 릴리스에서 조용히 틀려진다 —
그리고 틀린 문서는 없는 문서보다 나쁘다.

**다만 "찾는 법"만으로는 부족했다** (2026-08-24). 276 verb · 37 그룹에서 `--verb` 로 좁히려면
**어느 접두를 고를지**를 이미 알아야 하는데, 카탈로그는 그 질문에 싸게 답하지 않는다. 그래서
스킬 문서는 **작업 → 그룹 지도**를 싣는다. 그건 verb 목록이 아니다 — 그룹은 훨씬 느리게
움직이고(3주에 33→37), 코드펜스에 두면 **아래 가드가 그 지도를 검사한다.** 경계는 이렇다:

| 싣는다 | 싣지 않는다 |
|---|---|
| 작업 → **그룹** (한 줄씩, 가드가 검사) | verb 이름·플래그·시그니처 전량 |

가드가 이 규칙을 지킨다:

문서에 카탈로그에 없는 명령이 등장하면 가드가 **실패**한다. 실행법은 아래 참조.

## 가드는 로컬에서 돌린다 (CI 없음)

이 저장소는 **문서 집합**이라 빌드도 배포도 없다. 유일한 자동 검사가 위 드리프트 가드이고,
그건 `moumd` 바이너리를 필요로 한다 — moumd 는 비공개 배포라 여기 CI 에서 구할 수 없다.

**판정할 수 없는 CI 를 두지 않는다.** 영구히 붉은 잡은 "붉음을 무시하는 습관"만 만들고,
반대로 도구가 없다고 초록으로 넘기면 그건 거짓 초록이다. 그래서 워크플로를 두지 않는다.

```bash
MOUMD_BIN=/path/to/moumd scripts/check-no-invented-verbs.sh
# OK: 문서의 moumd 명령 <N>건이 모두 카탈로그에 존재한다 (카탈로그 verb <M>개)
#     N 은 문서를 고칠 때마다, M 은 릴리스마다 움직인다 — 숫자가 아니라 `OK:` 를 봐라.
```

문서를 고칠 때 이 한 줄을 돌려라. `moumd` 가 없으면 **exit 2(판정 불가)** 다 — 통과가 아니다.

> 이 가드를 자동화하고 싶다면 자리는 여기가 아니라 **moum-ops 레포**다. 거기엔 moumd 가
> 이미 빌드돼 있고, 카탈로그의 권위도 거기서 나온다.

## 스킬로 로드하려면

`SKILL.md` 는 `name`/`description` frontmatter 를 갖고 있어 Claude Code 스킬로 바로 뜬다.
**사본을 만들지 마라** — 링크로 걸면 정본이 하나로 유지된다.

```bash
ln -s "$PWD/skills/moumd-cli" ~/.claude/skills/moumd-cli
```

`description` 이 *"언제 이 스킬을 부를지"* 의 판정문이다. 문구를 고치면 로드 조건이 바뀐다.
